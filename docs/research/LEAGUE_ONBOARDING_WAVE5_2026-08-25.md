# League Onboarding — Wave 5 (2026-08-25)

Six fresh candidates plus two retries of wave 4's mint failures (Castlevania III, Power Blade), using the frame-aware, screen-visually-confirmed technique wave 4's synthesis recommended.

## Both wave-4 mint failures were retry successes — and both had a real, findable root cause

**Castlevania III: Dracula's Curse.** Wave 4 called this a genuine unskippable-boot property. It wasn't. The opening backstory text crawl LOOKS unskippable under a blind RAM-diff heuristic (scrolling text + border animation produces high churn indistinguishable from gameplay) but is actually skippable via START — confirmed by directly rendering and looking at frames, not just diffing RAM. A second, independent trap compounded the first: once past the crawl, START doubles as PAUSE, and wave 4's periodic-START mash schedule happened to keep landing on a paused read, which reads identically to a frozen demo under any RAM-divergence check. A pulse-by-pulse sweep found the live/unpaused window directly. **Root cause: a probing-technique limitation, not a game property** — exactly what wave 4 predicted before it had the receipts to prove it.

**Power Blade.** Also a retry success, also confirmed via visual frame inspection rather than RAM-diff alone (title → difficulty-select → an unskippable rooftop cutscene that auto-advances under pure NOOP → sector-select map → live gameplay). The retry agent caught and fixed a bug in its own methodology mid-session (a stale-unstepped-environment screenshot bug that briefly made 7 different button holds look pixel-identical) before trusting any result — worth noting as the same "verify, don't assume" discipline this project's own history keeps rewarding. Once live, it hit a real early wall: three independent methods (hold-right, hold-left, mixed-action solver search) all converge on the identical ~86-88 world-unit ceiling, with the agent still visibly active (OAM churning) throughout — a genuine skill/route wall just past spawn, not a broken mint or a frozen frontier with no explanation.

## A real, useful process finding: `nes_core.NESEnvironment` is not actually interpreter-only in this build

The Batman - Return of the Joker attempt needed to distinguish a real boot hang from the Journey to Silius-class ASM-CPU flat-trace anomaly (wave 4). Rather than reuse wave 4's own `nes_core.NESEnvironment` cross-check verbatim, this attempt checked the assumption first: direct code inspection (`nes_core/src/python.rs`) shows `NESEnvironment` exposes no `set_disable_asm_cpu` at all and constructs `Nes::new()` with the same `disable_asm_cpu=false` (ASM-CPU-on) default `Pool` uses — so bare `NESEnvironment` was never a true interpreter-only path in this build to begin with. The correct check is `nes_core.Pool(num_workers=1)` with `pool.set_disable_asm_cpu(True)` explicitly. Using the real toggle, Batman - Return of the Joker's boot hang reproduced byte-identically in both ASM and true-interpreter modes — ruling out the ASM-CPU anomaly cleanly (the hang is instrument-independent) rather than leaving it ambiguous. **This correction matters for every future onboarding pass that needs the interpreter-only cross-check** — citing `NESEnvironment` as "interpreter-only" is itself now a known-wrong assumption to avoid repeating.

## Synthesis

**6 of 8 landed SOUND_ADVANCING** (Mega Man 3, Ninja Gaiden III, Double Dragon II, Bad Dudes, and both retries — Castlevania III and Power Blade). **2 are SOUND_GAME_STOPS** with named, diagnosed causes (Shatterhand's likely lives-underflow; Power Blade's confirmed-real early wall, cross-validated by three independent methods). **1 mint_failed** (Batman - Return of the Joker — a genuine, instrument-independent boot hang, confirmed not to be the ASM-CPU anomaly via the corrected interpreter-only toggle).

**The recurring lives-underflow shape**: four games this wave and last (Mega Man (USA), Mega Man 3, Shatterhand, Bad Dudes) all had `discover_observables.py`'s top-ranked lives candidate read 0 at the actual root state — the exact class of bug root-caused and fixed for Mega Man (USA) earlier this session (commit `340c3e4`). Only Mega Man (USA) and Shatterhand show it visibly starving the frontier; the other two didn't stall visibly this wave but carry the same latent risk for a longer campaign. **This is now clearly a general tool defect** (`lives_from_death_drives()`'s `reaches_empty` check is trivially satisfied whenever a candidate's own start value is already 0), not a one-off — a dedicated pass fixing the discovery tool itself, rather than patching each game's config by hand as it's noticed, is the right next lever. Power Blade's retry shows the correct manual workaround in the meantime: catch a start=0 top candidate before wiring it and substitute the next-ranked, verified-nonzero one.

**Discipline that held up this wave:** two independent retry successes came from actually looking at rendered frames rather than trusting a RAM-divergence heuristic alone, exactly the lesson wave 4 named. A stale assumption about `NESEnvironment` being interpreter-only was caught and corrected before it could produce a false "ASM-CPU anomaly ruled out" verdict. A bug in a retry agent's own screenshot-capture method was caught and fixed mid-session rather than banked. Every mint_failed and every flagged-but-unconfirmed caveat was reported as such, not smoothed over.
