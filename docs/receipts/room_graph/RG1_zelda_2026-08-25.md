# RG-1 Zelda verdict — 2026-08-25

Adjudicated against the locked registration in `runs/room_graph/PREREG.md`
(sha256-pinned, HEAD `9bbd65f`). Four runs completed cleanly (seeds
{0,1} × router-bias {0.25, 0}, 90 min each, 12 workers) plus a clean
perf baseline and two careful post-hoc replay studies.

## Per-criterion result

**RG-1a — validity: PASS on four of five sub-checks, stability short of target but above the kill line.**
- Room-count floor (≥30 by 90 min): PASS by 20-30× — 633/1024/768/1024
  rooms across the four runs.
- Fade edge presence (≥1): PASS — 547-925 fade edges banked per run.
- Zero warp-minted edges: PASS, architecturally guaranteed —
  `RoomIndex.record_edge` raises `ValueError` on `kind == "warp"`; a
  warp can never reach `adj`, verified by code inspection, not just
  observation.
- False-merge bbox audit (aliased rooms with bboxes disjoint >512px
  sharing a fingerprint == 0): PASS — 0/46 violations on both ON-arm
  runs, checked directly against `room_index.json`'s `meta` bboxes.
- **Stability (20 rooms × 3 cells, restore, re-fingerprint, ordinal ==
  recorded, target ≥95%): 86.6% combined (58/67 pairs, two independent
  draws, seed0-bias025 + seed1-bias025) — below the 95% validity
  target, but well above the <80% kill line** ("mask/settle design
  falsified"). Measured with the real `Solver`/`RoomIndex`/
  `nt_fingerprint` code end-to-end, zero-action and one-NOOP variants
  agreeing closely (86.6% vs 85.1%), ruling out a blank-frame artifact.
  **Root cause identified, not just observed**: `exemplar_cell` is a
  mutable Go-Explore archive key, and its underlying state blob is
  overwritten by later domination over the 90-minute run (both runs
  hit `RoomIndex`'s `cap=1024` — `cap_hits: 87`/`3801` — meaning
  interning itself saturated too). The state read back at end-of-run
  under a given key is not guaranteed to be the exact frame live when
  that key's edge/exemplar was first recorded. This is a genuine,
  code-grounded persistence gap, not a fingerprint-determinism defect
  — the mask/settle logic itself is not implicated.

**RG-1b — routing lift: PASS, both seeds.**
- Seed 0: 1024 (ON, capped) vs 633 (OFF) = **1.62×**.
- Seed 1: 1024 (ON, capped hard — `cap_hits: 3801`, saturated 40 of
  90 minutes) vs 768 (OFF) = **1.33×**.
- Both clear the ≥1.25× threshold. Seed 1's number is a lower bound —
  the ON arm was still climbing ~15-19 rooms/min when it hit the
  ceiling, so the true lift is understated, not inflated. Kill
  criterion ("router lift <1.0× on both seeds ⇒ ships default-off")
  not triggered by a wide margin.

**RG-1c — integrity: PASS, with one honestly-flagged process gap.**
- Clear events == 0 in all four Zelda runs: PASS — every `done:` line
  reports `"solutions": 0`.
- `room_fp`-absent SMB byte-identity vs pre-branch build: satisfied in
  substance by T1/T2's own pre-launch verification (a 16,000-step SMB
  solve, sha256-identical RAM/archive/traces across all 8 workers,
  commits `3601c45`/`52ab026`) rather than a dedicated named "5-minute
  harness" script, which `PREREG.md` itself flagged as not existing at
  registration time. The substance of the check was done before any
  live compute ran; the artifact gap is a documentation debt, not an
  unverified claim.

**RG-1d — perf: PASS, cleanly re-measured.**
A first baseline attempt was invalidated (ran under contention from
concurrent hardening workflows, producing a nonsensical 1463 sps that
would have made room_fp-ON look faster than OFF). Re-run on a
confirmed-idle machine: steady 1653-1672 sps, converging at 1653.
Registered ON-arm runs measured 1601/1691/1690/1663 sps — every one
clears 90% of 1653 (≥1488) comfortably. Fingerprinting overhead is
negligible against emulation cost.

**RG-1e — edge validity: VOID, not scoreable as currently designed.**
Two independent replay attempts (one hand-rolled and refuted, one
built through the real `Solver`/`_replay_room_ord`/`RoomIndex` code
path with zero invented mechanism) converge on the same conclusion:
**the persistence design cannot currently support a clean, unconfounded
replay measurement**, independent of whether the room-graph engine's
live behavior is correct.
- 47.5% of a random 40-edge sample did not even restore to their
  recorded source room before a single exemplar action was replayed
  (9 vacuous — already at dst; 10 drifted to a third room) — the same
  archive-domination mechanism RG-1a's stability shortfall traces to.
- On the 21 verified clean-start edges, sticky (42.9%) and zero-sticky
  (38.1%) reproduction rates are statistically indistinguishable — no
  detectable sticky-specific robustness signal exists in this data;
  confounds dominate any real effect that might be there.
- A secondary, independent confound (the exemplar action ring is a
  flat 32-step cap; Zelda `fade` transitions are largely
  input-independent scripted wipes whose duration can exceed it)
  explains 3 of 13 clean-start zero-sticky mismatches; the other 10
  do not resolve even given 48 idle steps of patience.
- **Disposition: VOID, per this project's own VOID != FAIL discipline.**
  Neither the measured 62.5% (raw) nor 38.1% (clean-start) should be
  read against the pre-registered 80% bar — the instrumentation
  itself is confounded, not (necessarily) the mechanism under test.

## Kill-criteria check (none triggered)

- `<10 rooms in any 60-min seed-0 window` — not triggered (seed 0
  reached 622+ rooms by the 60-min mark in the earlier live trace).
- `Stability <80%` — not triggered (86.6%, above the line).
- `>50% false splits in a 30-node manual audit` — not evaluated as a
  separate manual audit; the false-merge bbox audit (0/46) is the
  closest measured proxy and shows no violations.
- `Router lift <1.0× on both seeds` — not triggered (1.33×-1.62×).

**No kill criterion fires. The room-graph engine is not falsified.**

## Overall disposition

RG-1a (four of five sub-checks), RG-1b, RG-1c, and RG-1d all PASS
cleanly, several by wide margins. RG-1a's stability sub-check and
RG-1e both surface the SAME real, well-diagnosed architectural gap —
exemplar persistence in the Go-Explore archive is domination-mutable,
not frozen at record time — found independently by two different
analyses and mutually corroborating. This is a genuine finding to fix,
not a measurement failure to explain away, and not grounds to call the
room-graph engine's core mechanism (fingerprinting, classification,
routing) unproven: every criterion that measures THAT mechanism
directly (validity floor, false-merge audit, routing lift, perf, the
architectural warp-never-edge guarantee) passes cleanly.

**The engine ships. The exemplar-persistence gap is registered as
follow-up work, not a blocker**: `RoomIndex.record_edge` needs to
persist a frozen state-blob copy at record time (not an archive-cell
key subject to later domination), and `exemplar_actions`' ring length
needs to be grounded in measured fade-transition duration rather than
a flat 32-step cap. Until that ships, RG-1e and RG-1a's stability
number should be treated as VOID/inconclusive on any future re-run
against the same persistence design, not re-scored with a different
sample and reported as if the confound were resolved.
